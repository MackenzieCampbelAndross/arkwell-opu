# ARKWELL OPU: Selective Constraint Propagation Protocol

## 1. Motivation and Objective
In naive parallel optimization engines, committing a state change requires broadcasting the updated state vector $\mathbf{x}'$ to all processing elements (PEs), creating an $O(P \cdot N)$ communication bottleneck at every step.

The **Selective Constraint Propagation Protocol (SCPP)** restricts communication so that an update $\Delta x_i$ is multicast **only to PEs hosting variables or constraints directly coupled to $x_i$**.

---

## 2. Mathematical Subscription Model

### 2.1 PE Variable and Constraint Partitioning
Let the set of variables $V$ be partitioned across $P$ processing elements:
$$V = \bigcup_{p=0}^{P-1} V_p, \quad V_p \cap V_q = \emptyset \; (p \neq q)$$

### 2.2 PE Constraint Subscription Set
A processing element $p$ is interested in state updates on variable $x_i$ if and only if $x_i$ shares a constraint with at least one variable owned by $p$:

$$\text{Subscribers}(x_i) = \{p \in \{0, \dots, P-1\} \mid \exists j \in V_p \text{ such that } (i, j) \in E\}$$

For Maximum Independent Set, $\text{Subscribers}(x_i)$ is exactly the set of PEs hosting open neighbors $\mathcal{N}(i)$.

---

## 3. Communication Cost Analysis

### 3.1 Global Broadcast (Naive - Configuration B)
For a batch $B$ of committed updates:
- Message count: $|B| \cdot P$
- Byte volume: $|B| \cdot P \cdot \text{sizeof}(\text{Update})$

### 3.2 Selective Propagation (Configuration D)
For a batch $B$:
- Targeted recipients for $u_i \in B$: $\text{Subscribers}(u_i)$
- Message count: $\sum_{u_i \in B} |\text{Subscribers}(u_i)|$
- Byte volume: $\sum_{u_i \in B} |\text{Subscribers}(u_i)| \cdot \text{sizeof}(\text{Update})$

In sparse graphs with density $d \ll 1$, $|\text{Subscribers}(u_i)| \ll P$, providing substantial bandwidth savings and reduced cache invalidation overhead.

---

## 4. Consistency & Correctness Invariants
1. **FIFO In-Order Delivery:** Updates sent to any subscriber PE must arrive in deterministic commit sequence.
2. **Snapshot Coherence:** Before a PE begins evaluating candidate moves for round $t+1$, all notifications generated by batch $t$ must be acknowledged and applied to its local constraint caches.
3. **No Phantom State:** PEs must not operate on stale constraint slack.
